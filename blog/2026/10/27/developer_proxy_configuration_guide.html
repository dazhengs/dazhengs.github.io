The Complete Guide to Configuring and Unsetting Proxies for Developer Tools ​

When working behind corporate firewalls or restricted networks, configuring developer tools to correctly route traffic through a local or remote proxy—whether HTTP or SOCKS5—is a routine necessity. However, because different developer utilities manage their network layers independently (some read system environment variables, while others rely strictly on local configuration files or daemon configurations), knowing how to both set and unset proxy settings cleanly across your toolchain is crucial.

This guide provides tested, copy-pasteable configuration and removal recipes for:

  • Version Control & Shell: Git, curl, wget
  • Package Managers & Runtimes: pip, npm, yarn, Go (go get / go install), apt
  • Containerization: Docker Daemon (docker pull), Docker Client, and Docker Compose

Conventions Used in This Guide ​

Throughout this document, replace the placeholder addresses with your actual proxy IP and port:

  • HTTP Proxy Example: http://127.0.0.1:11082
  • SOCKS5 Proxy Example: socks5://127.0.0.1:11082 or socks5h://127.0.0.1:11082

Tip (socks5:// vs. socks5h://): Always favor socks5h:// when supported. The trailing h forces hostname resolution (DNS lookups) to happen on the proxy server rather than locally, preventing DNS leakage or poisoning.

1. Universal Environment Variables ​

Many CLI tools (curl, wget, go, Python scripts) automatically inspect standard shell environment variables.

Temporary (Current Session) ​

bash
# HTTP proxy
export http_proxy="http://127.0.0.1:11082"
export https_proxy="http://127.0.0.1:11082"
export all_proxy="http://127.0.0.1:11082"
export no_proxy="localhost,127.0.0.1,localaddress,.localdomain.com"

# SOCKS5 proxy
export http_proxy="socks5h://127.0.0.1:11082"
export https_proxy="socks5h://127.0.0.1:11082"
export all_proxy="socks5h://127.0.0.1:11082"

Unset (Current Session) ​

bash
unset http_proxy https_proxy all_proxy no_proxy
unset HTTP_PROXY HTTPS_PROXY ALL_PROXY NO_PROXY

2. Git ​

Git supports proxying for both HTTP/HTTPS endpoints and SSH endpoints.

HTTP / HTTPS Repositories (https://github.com/...) ​

Set ​

bash
# SOCKS5 (recommended with remote DNS)
git config --global http.proxy socks5h://127.0.0.1:11082
git config --global https.proxy socks5h://127.0.0.1:11082

# Or HTTP
git config --global http.proxy http://127.0.0.1:11082
git config --global https.proxy http://127.0.0.1:11082

Unset ​

bash
git config --global --unset http.proxy
git config --global --unset https.proxy

SSH Repositories (git@github.com:...) ​

Git's http.proxy setting does not affect SSH traffic. Configure your OpenSSH client (~/.ssh/config on Linux/macOS or C:\Users\<User>\.ssh\config on Windows):

Set (macOS / Linux using netcat) ​

ssh
Host github.com
    User git
    ProxyCommand nc -X 5 -x 127.0.0.1:11082 %h %p

Set (Windows Git Bash using connect.exe) ​

ssh
Host github.com
    User git
    ProxyCommand connect -S 127.0.0.1:11082 %h %p

Unset ​

Simply remove or comment out the ProxyCommand directive in ~/.ssh/config.

3. Python (pip) ​

Pip provides a built-in configuration utility that updates pip.conf / pip.ini.

Set ​

bash
# SOCKS5 (requires: pip install pysocks)
pip config --user set global.proxy socks5h://127.0.0.1:11082

# HTTP
pip config --user set global.proxy http://127.0.0.1:11082

Unset ​

bash
pip config --user unset global.proxy

Verification ​

bash
pip config get global.proxy

4. Node.js (npm & yarn) ​

npm ​

Set ​

bash
# SOCKS5
npm config set proxy socks5://127.0.0.1:11082 --global
npm config set https-proxy socks5://127.0.0.1:11082 --global

# HTTP
npm config set proxy http://127.0.0.1:11082 --global
npm config set https-proxy http://127.0.0.1:11082 --global

Unset ​

bash
npm config delete proxy --global
npm config delete https-proxy --global

Yarn Classic (v1.x) ​

Set ​

bash
yarn config set proxy http://127.0.0.1:11082 -g
yarn config set https-proxy http://127.0.0.1:11082 -g

Unset ​

bash
yarn config delete proxy -g
yarn config delete https-proxy -g

Yarn Berry (v2+) ​

Yarn Berry manages settings in .yarnrc.yml:

Set ​

bash
yarn config set httpProxy "http://127.0.0.1:11082"
yarn config set httpsProxy "http://127.0.0.1:11082"

Unset ​

bash
yarn config unset httpProxy
yarn config unset httpsProxy

5. Go (go get, go install) ​

The Go toolchain honors standard shell environment variables.

Module Mirror vs. Raw Proxy ​

  1. Option A: Public Module Proxy (Direct Go Mirror)

    bash
    # Set official or alternate module proxy
go env -w GOPROXY="https://proxy.golang.org,direct"

# Reset to default
go env -u GOPROXY

  2. Option B: Network Proxy via Environment

    bash
    # In your shell profile (~/.bashrc or ~/.zshrc)
export http_proxy="socks5h://127.0.0.1:11082"
export https_proxy="socks5h://127.0.0.1:11082"

6. curl & wget ​

curl ​

Persistent Configuration (~/.curlrc) ​

Add the following line to ~/.curlrc:

ini
# SOCKS5
proxy = "socks5h://127.0.0.1:11082"

# Or HTTP
proxy = "http://127.0.0.1:11082"

To unset, delete the proxy line from ~/.curlrc.

Ad-hoc Command Line ​

bash
curl -x socks5h://127.0.0.1:11082 https://httpbin.org/ip

wget ​

Persistent Configuration (~/.wgetrc) ​

Add the following lines to ~/.wgetrc:

ini
use_proxy = on
http_proxy = http://127.0.0.1:11082/
https_proxy = http://127.0.0.1:11082/

To unset, remove or comment out these lines (# use_proxy = on).

Note: wget does not natively support SOCKS proxies via .wgetrc. Use an HTTP proxy or a wrapper tool like proxychains.

7. Debian / Ubuntu Package Manager (apt) ​

apt reads configuration directives located in /etc/apt/apt.conf.d/.

Set ​

Create a configuration file (e.g., /etc/apt/apt.conf.d/99proxy):

bash
# SOCKS5
sudo tee /etc/apt/apt.conf.d/99proxy << 'EOF'
Acquire::http::Proxy "socks5h://127.0.0.1:11082";
Acquire::https::Proxy "socks5h://127.0.0.1:11082";
EOF

# HTTP
sudo tee /etc/apt/apt.conf.d/99proxy << 'EOF'
Acquire::http::Proxy "http://127.0.0.1:11082";
Acquire::https::Proxy "http://127.0.0.1:11082";
EOF

Unset ​

bash
sudo rm -f /etc/apt/apt.conf.d/99proxy

8. Docker (docker pull & Docker Compose) ​

Docker network traffic is split into two distinct layers:

  1. The Docker Daemon (dockerd): Pulls and pushes images (docker pull, image pulls triggered during docker compose up).
  2. The Docker Client / Containers: Traffic generated inside active containers or during build steps.

Crucial Networking Note for Docker on Linux:
The Docker daemon runs as an isolated systemd service. If your proxy server listens on 127.0.0.1, the daemon and containers may fail to connect because 127.0.0.1 refers to their own local namespace. On Linux host machines, consider using your host's LAN IP or the Docker bridge IP (often 172.17.0.1). On macOS/Windows Docker Desktop, use host.docker.internal.

Layer 1: Image Pulling (docker pull via systemd) ​

To route image pulls through a proxy on Linux:

Set ​

  1. Create a drop-in systemd configuration directory:

    bash
    sudo mkdir -p /etc/systemd/system/docker.service.d

  2. Create /etc/systemd/system/docker.service.d/http-proxy.conf:

    ini
    [Service]
Environment="HTTP_PROXY=http://127.0.0.1:11082"
Environment="HTTPS_PROXY=http://127.0.0.1:11082"
Environment="NO_PROXY=localhost,127.0.0.1,docker-registry.internal"

    (For SOCKS5, use Environment="ALL_PROXY=socks5h://127.0.0.1:11082")

  3. Reload systemd and restart Docker:

    bash
    sudo systemctl daemon-reload
sudo systemctl restart docker

Unset ​

bash
sudo rm -f /etc/systemd/system/docker.service.d/http-proxy.conf
sudo systemctl daemon-reload
sudo systemctl restart docker

Layer 2: Docker Client & Container Runtime (~/.docker/config.json) ​

To automatically pass proxy variables to containers and CLI build commands:

Set ​

Edit or create ~/.docker/config.json:

json
{
  "proxies": {
    "default": {
      "httpProxy": "http://127.0.0.1:11082",
      "httpsProxy": "http://127.0.0.1:11082",
      "noProxy": "localhost,127.0.0.1"
    }
  }
}

Unset ​

Remove the "proxies" block from ~/.docker/config.json.

Layer 3: Docker Compose ​

Docker Compose behaves depending on which part requires network access:

A. Pulling Images ​

If docker compose up needs to pull remote images, it relies on the Docker Daemon configuration detailed in Layer 1.

B. Passing Proxies into Services / Build Contexts ​

To pass proxy environment variables into services running under Docker Compose, define them in your .env file or directly inside compose.yaml:

yaml
services:
  app:
    image: node:20-alpine
    environment:
      - HTTP_PROXY=http://172.17.0.1:11082
      - HTTPS_PROXY=http://172.17.0.1:11082
      - NO_PROXY=localhost,127.0.0.1
    build:
      context: .
      args:
        HTTP_PROXY: http://172.17.0.1:11082
        HTTPS_PROXY: http://172.17.0.1:11082
